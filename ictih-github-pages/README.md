# ICTIH — Insurance Cybersecurity Threat Intelligence Honeypot

A GitHub Pages-ready, static portfolio project that presents a fictional insurance company alongside a **safe browser-only threat-event simulator**. It uses only HTML, CSS, and JavaScript.

## Safe-use statement

This repository is an educational simulator, not a public honeypot and not an intentionally vulnerable application. It does not receive network traffic, run server code, store accounts, accept real credentials, connect to a database, scan targets, or execute attack payloads. Every listed attack is a labeled synthetic event generated by a button in the visitor's own browser. Use the site only for coursework, demonstrations, and defensive data-analysis exercises.

## What is included

- Fictional Northstar Mutual landing, customer portal, claims, and operations views
- Nine simulated event types: port scan, failed/weak login, SQL injection, enumeration, privilege escalation, suspicious query, sensitive-data access, and data exfiltration
- Timestamped local event logging: source IP, target, username, severity, detection state, category, and risk weight
- Dashboard totals, risk score (0–100), risk level, distribution chart, severity bars, and history table
- CSV and JSON downloads for Python, R, or Excel analysis
- Browser `localStorage` persistence, demo-data loading, and reset controls

All policy numbers, people, counts, identifiers, addresses, and IP addresses are synthetic. Documentation-reserved IP space (`192.0.2.0/24`) is used for the default simulator IPs.

## Risk model

The experimental score adds each event's configured weight, divides by two, and caps the result at 100. It is deliberately simple for classroom discussion rather than an actuarial or underwriting calculation.

| Category | Weight |
|---|---:|
| Failed authentication / weak credential | 10% |
| Port scan / enumeration | 5% |
| SQL injection / suspicious query | 20% |
| Privilege escalation | 25% |
| Sensitive-data access | 20% |
| Data exfiltration | 20% |

Risk labels: Low (0–24), Elevated (25–49), High (50–74), Critical (75–100).

## Architecture

`index.html` provides the interface, `styles.css` provides responsive presentation, and `app.js` produces and visualizes synthetic events. The browser stores events under `ictih-security-events-v1`; exports are assembled entirely client-side. There is no backend, API, database, telemetry, or inbound request handling.

## Publish on GitHub Pages

1. Create a new GitHub repository and upload the contents of this folder (not the folder itself, unless you choose to publish from that subfolder).
2. In the repository, open **Settings → Pages**.
3. Under **Build and deployment**, select **Deploy from a branch**.
4. Select the branch (usually `main`) and folder `/ (root)`, then save.
5. GitHub will display the published URL after deployment. Updates may take a few minutes.

For a project site, the URL normally looks like `https://YOUR-USERNAME.github.io/REPOSITORY-NAME/`.

## Local preview

Open `index.html` in a modern browser. No package installation or server is required.

## Suggested portfolio talking points

Explain the distinction between this static simulation and a real honeypot: this project demonstrates event design, severity classification, risk scoring, dashboarding, and data export without exposing a vulnerable service. In a separately authorized, isolated lab, a backend implementation would require explicit scope, logging, access controls, and containment.
